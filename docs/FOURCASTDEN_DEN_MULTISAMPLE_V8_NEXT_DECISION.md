# v8之后：预注册DEN残差参数化对照，不自动延长训练

2026-11-13。本文只是下一轮申请方案；未启动额外训练、未拟合统计或生成新数据。

## 1. 已经得到什么证据

- 同方法从累计200继续520次至720：训练relative RMS3.804484→2.276034%，降低40.174961%；开发10.082082→6.725325%，降低33.294283%。所有训练72对/开发48对与两年29层均改善，说明更多更新确有收益。
- 训练仍高于Persistence1.722953%（1.321倍），开发仍高于1.992488%（3.375倍）；训练0/72对胜P、两年逐层0/29胜P。不能宣布拟合充分或实际预测有优势。
- 第10轮运行中pre-update loss均值0.175885，比第9轮0.192064低8.423658%；所有72对第10次访问低于第9次。**没有明确平台证据**。同一遍历里的模型在更新，这些描述不能取代最终统一模型评价。
- 新520次都clip1，clip前L2约11.63—16.52且有限；不是已证明爆炸或clip导致失败。逐层normalized MSE最高层与relative RMS最高层不完全一致，提示损失尺度/物理指标有差异，但未证明改loss更好。
- 全部120对最终0非正/0非有限，无裁剪。仅当前窗口物理正值通过，不保证未见数据正值。

因此不能说“直接DEN失效”或“全部问题只是数据少”。模型仍在优化；而强1小时Persistence和剩余高层误差，使预测当前场上的小变化量成为值得测试的结构假设。

## 2. 推荐优先级：残差式DEN，严格只改变输出语义

下一轮第一优先建议为**残差式DEN对照**，不再自动将当前任务追加到1440。不同时调整lr、clip、数据量、网络、loss或正值约束。

使用原v3训练统计，无新拟合。每个DEN原生层k，设原始g/cm³下：

`n_current=(DEN_current-mean2021_k)/std2021_k`

原输入的对应DEN通道就是该当前标准化状态。新网络原始DEN输出解释为标准化增量`r_pred`，未来标准化预测为：

`n_next_pred=n_current+r_pred`

反变换：`DEN_next_pred_kg_m3=(n_next_pred*std2021_k+mean2021_k)*1000`。

训练仍用原cos纬度DEN-only normalized MSE，在`n_next_pred`与原真实`n_next_target`之间计算。等价的增量目标为`(DEN_next-DEN_current)/std2021_k`，均值抵消，不从2022或Swarm拟合任何新统计。可复用既有2021统计而不是静默生成残差方差；如后续希望按残差方差标准化，应另立版本、仅训练数据拟合并作为额外因素。

- `r_pred=0`应解析地还原Persistence，先用CPU单元测试核验。
- 线性残差不保证正值。保留非正统计和未裁剪ordinary误差；不混入log/softplus/裁剪。
- 原177/4/171架构、随机seed20261113、初始参数SHA b3c177d2...、DEN142:171监督、AdamW1e-4/constant/clip1/FP32均保持。
- 新版本从相同种子随机初始化，不加载v8权重。原始输出语义不同，不能声称旧checkpoint兼容；其他142输出仍不受直接监督，也不能反馈自回归。
- 这不是作者完整Flow复现，而是本项目明确版本的DEN-only增量目标工程对照。
- 当前真实DEN来自输入时刻，目标真实DEN只能进入loss；未来TN/风/Z/DEN毒化检查继续，外部未来驱动仍为HINDCAST。

## 3. 怎样避免把恢复协议差异误当参数化差异

v8源自v7在200处完成评价后保存的checkpoint，本轮不证明它与一次性无中断720步逐位相同。严谨残差对照应事先选择以下协议之一，不能事后忽略差异：

**推荐匹配版本：** 从同种子新残差模型开始，先固定200步，再按与v7相同的最终72训练/48开发评价、保存/恢复路径，之后独立预算接续520至720，最后统一评价。200处开发结果仅记录，不用于选择checkpoint、学习率、步数或决定是否继续；除预注册安全故障外继续到720。所有配置在第一阶段前一次性冻结，不根据200结果调整。

这样与已有Direct v7/v8在数据、顺序、更新次数和阶段边界上对应，主动改变因素仅DEN输出语义；不重跑已有Direct。仍不声称任何一组与无中断轨迹已验证逐位等价。

若下一轮希望**只在720做一次开发评价且完全不设200中间评价**，应明确为新的统一协议。与旧v8可作条件历史比较，但不能声称运行路径完全相同；如严格需要，应另授权一条同协议新Direct控制，与残差共同冻结。不能把额外控制轨道/训练伪装成已经授权。

## 4. 候选预算与评价

推荐匹配版本需要下一轮**单独授权两次分阶段GPU任务**，不是本轮继续：

- 阶段1：200训练+72训练评价+48开发评价+1恢复=321forward。
- 阶段2：源恢复探针1+520训练+72训练评价+48开发评价+最终恢复1=642forward。
- 总计720更新、963forward；前200的更新顺序0—71循环，后520从56开始，累计每对10次。
- 保持每任务监督300秒，两个合计上限600秒，GPU20GiB/CPU树8GiB，至少20GiB磁盘空闲。仅申请预算，未执行。
- 依据v7/v8实测合计约210.7秒，1.5倍约316秒；阶段321/642预算只是控制上限，不把外推当实测。720纯更新预计约86秒级，模型/语义变化仍须资源预检。

## 5. 其他候选为何暂不混做

- 更多数据：两年只有三月短窗口、72个强相关训练对，不能支持64.7M参数模型的广泛泛化结论。但当前训练集本身仍未胜P，先用参数化对照减少混杂；扩季节/驱动范围应另申请数据生成，统计只训练拟合，2022保持开发身份，2023历史已查看窗口不得改称盲测。
- log-DEN：值得后续独立对照，可研究log增量，但需要明确输出定义/反变换/统计，不能与线性残差同轮同时改。不得声称本轮已证明log更好。
- 优化策略：持续clip和仍下降是研究动机，不是修改阈值/学习率的依据。若研究clip或lr，应一次只改一个、固定样本与更新预算，不能无限加步。
- 全171通道：风/组分预热质量与监督资格未全部通过；不因DEN训练工程闭环就增加未验收标签或宣布科学训练PASS。
