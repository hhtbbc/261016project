# V33 执行建议：优先核实 ZG 登记与条件敏感性

## 主研究问题

确定原生 ZG 的零面及模型纬度关系是否足以限制条件密度比较的物理解释。保留原 Global，不增加校正参数、不修改模式或正式高度接口。V32 的历史信号不足以训练门控，且业务发布时戳未闭合。

## 顺序和停止条件

1. 直接执行元数据和源码证据核查，使用 V2/V2.1、冻结模型输出、Swarm GRS80 合同和已有控制资料。记录版本、单位、参考面、纬度定义、适用域及发布时钟。授权后先在已使用开发样本抽查原生垂直梯度 dlnρ/dh 和八列共同支持。无需新数据和积分。
2. 若取得版本适配的独立零面和纬度依据，且高度误差幅度有物理来源，事前锁定零偏移、固定对称正负偏移及取值级数。幅度只来自外部证据，未来残差不能用来优化、选择或解释为真实高度偏差。缺幅度或可信共同域时停止于证据及每米梯度，不设任意扰动。
3. 另授权后才对冻结开发样本开展条件性只读扰动。每个偏移和零基线使用相同 UTC、轨迹及两帧四角，检查零权重列、先记共同有效 ID、覆盖损失及拒绝原因。严禁外推、补值、误差筛样。按相同分母并列 RMSE、Relative RMS、P95、低纬绝对 Relative Bias。独立验证梯度、单位、覆盖和残差计算。敏感性结论不解除正式高度门禁。

## 角色、输入与资源

春季 03-23/24/25 及两秋日仅作开发资料，V30 历史身份保留。初步工作不启用新验证日，未来冻结候选及整日分块角色后才进入新验证/测试；V20 夏冬目标持续封存。只使用已有冻结原件、元数据、轨迹质量及独立高度证据。若缺版本明确的外部说明或产品不确定度，后续可需新独立参考资料，暂无新观测下载要求。中心81日 GFZ 均值、终版 Kp 或 POD 值在业务门控中须有合格 as-of 记录。

单 CPU 进程，直接阶段 ≤600 秒、≤4 GiB、轻量新增 ≤150 MiB。条件阶段同级预算起步，现有 NetCDF 原位读取，无需新 TIE-GCM 积分或 GPU。若外部证据未齐、任一偏移八列超界、不能形成共同域或资源门槛未通过，停止并报告。研究假设限于条件性敏感性，模型/初态/预热/观测误差因果仍须独立控制。保持 V20 与轨道、AI、DART 门禁。
