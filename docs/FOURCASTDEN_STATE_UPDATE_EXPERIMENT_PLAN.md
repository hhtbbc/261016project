# FourCastDEN状态更新周期：已有证据与下一次受控设计

2026-10-31；本轮仅复用已有12小时指标，不新增网络forward，不给出“最佳修正周期”。

## 已有证据

Jan4和Mar24四模型都有同01时起点、02—13时的完整12步预测，前6步与旧六小时结果一致。不同日期/时效的模型排序变化，高层与顶部误差不同，误差也非严格单调。完整现有曲线保存在`results/fourcastden_orbit_integration_v1/existing_error_growth.csv`，包括参考400—500km相关原生层组、固定upper20—28和顶部；这些坐标不能相互替代。

两日期不支持全年更新频率结论，也没有应用可接受的真实沿轨误差阈值。单次一小时虚拟轨道差无法证明6小时或12小时更新最优。新高度重建还发现Mar24 Flow在少量列中反推平均分子量超出源模型4—32范围，这说明除了DEN正性，长时多场热力一致性也应进入更新实验诊断；不是对模型训练目标作了新调参。

## 优先设计：同一12小时任务，6小时处一次理想状态更新

先固定Jan4/Mar24、原四套模型和全部数据/统计；不按哪个日期误差更小替换日期。

1. 自由预测组：直接复用已有01→13的12小时轨迹，不重跑。
2. 理想更新组：前6小时复用原轨迹，在07时用参考真实TIE-GCM状态重新初始化，再预测08—13。History需要06/07两个合法真实历史帧，明确其额外信息。必须另行授权GPU推理。
3. 这是**离线TIE-GCM全状态重初始化/理想更新上界**，不是实测卫星或大气观测同化，更不能称业务中可获得07时全球真值。
4. 只在重初始化后6小时比较同目标时间，报告更新瞬间跳变、全层与上层DEN相对/绝对误差、顶部/极区、温度/风/Z、反推高度有效率，以及额外加载、推理与状态获取成本。
5. 若以后接轨道，两组都从相同初始轨道连续传播；大气状态可更新，卫星轨道不能偷偷用SP3重置。更新场的时间接缝需明确插值规则、查询有效性与积分收敛。

现有原始00—13帧足够提供上述理想更新条件，无须先下载24小时数据。新增预计8个6步序列、48次forward；在正式申请时以旧性能CSV重新核算GPU/RAM/文件量，不能把当前CPU轨道预算挪作GPU授权。本轮没有执行。

## 为什么现在不能检验12小时更新周期

12小时轨迹只到第一次12小时更新边界，要看到该次更新后的效果，需要至少再预测一段，通常形成更长共同评价任务，并补足对应参考与条件。当前不能用12小时终点误差冒充“每12小时更新的性能”。24小时/更长任务须单独预注册数据与预算。

## 真实业务更新还缺什么

需要明确观测类型、可获得时间和延迟、空间覆盖、从稀疏观测到171通道全状态的恢复/同化方法、驱动预报来源、状态不确定性，以及实际轨道应用容许误差。未来TIE-GCM场只适合离线理想对照，不能伪装成未来业务观测。

训练损失/层权重/模型融合仍只能用独立训练和2022验证选择；这些已查看2023窗口继续保持独立测试用途。本设计不解除122帧科学训练门禁。
